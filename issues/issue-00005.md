Reported by the developer (2026-10-20): repeated Keychain permission prompts from ClaudeMon despite choosing Always Allow.

**Cause:**
- Claude Code (2.1.304) writes `Claude Code-credentials` with `/usr/bin/security add-generic-password -U …`, and in some paths runs `delete-generic-password` first.
- The item is rewritten on every token refresh: `mdat` was 2026-10-20 11:49Z.
- After a rewrite, the access list trusts only `security`, so the "Always Allow" granted to ClaudeMon is gone. ClaudeMon read the item with `SecItemCopyMatching` on every limits refresh, so it prompted again after each Claude Code token refresh.
- Each rebuild also gets a new ad-hoc signature, which adds more prompts during development.

**Fix:** read through `/usr/bin/security find-generic-password -s "Claude Code-credentials" -w`. The item already trusts that tool, so there is no prompt. Verified: no SecurityAgent dialog, `mdat` unchanged, and the request reached the usage endpoint (it returned 429 at the time).

**Spec impact:** still meets R-CMLIM-001 and R-CMLIM-002. ADR-3's consequence "macOS asks the owner to allow Keychain access" and R-CMLIM-001.T1's GIVEN clause ("ClaudeMon has Keychain access (Always Allow)") are now out of date and need a clarification.
